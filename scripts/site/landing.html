What sets it apart

Scriptable, and ready for your assistant.

The whole collection sits behind a versioned REST API. A built-in MCP server lets an assistant read it and, only if you allow it, change it.

REST API Scoped tokens, an OpenAPI contract, idempotent writes.
MCP Same API, scopes and Undo as any other client. Write tools stay off until you enable them.
Undo Every change leaves an audit event with an Undo link, whoever made it.
CLI An admin CLI for tokens, setup and migration.

Questions collectors ask

I do not run servers.

The demo needs no install. To keep your own, you need a computer at home or a NAS, and one Docker Compose path.

Is it safe to let an assistant into my data?

Tokens are read-only by default. Write tools stay off unless you enable them, scopes limit what a token can do, and every change has an Undo link.

What if the project disappears?

It is open source under MIT. Your data is a plain database file in one folder, plus exports.

Does it replace Rebrickable or BrickLink?

No. It uses your own keys for catalogue data and prices, and bundles none of their data.

Is it finished?

No. It is pre-1.0 and used daily by its maintainer on about 200 set copies. Planned work is labelled planned on the roadmap.

Start in five commands

Docker Compose on your own machine. Then open http://localhost:3333. Moving an old collection over? brickwork migrate imports it read-only.
